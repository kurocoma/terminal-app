# terminal-app

Claude Code / Codex の並行セッションを監視する Windows 11 常駐タイルダッシュボード（Electron）。
**どのセッションが止まったかをひと目で識別し、1 クリックで対象ウィンドウ（Cursor / ターミナル）に切り替える。**

- **引き継ぎ: `docs/handover-20260928-codex.md`**（別の担当者・Codex が最初に読む。残課題・作業ルール・環境の勘所）
- 要件: `docs/spec.md`（REQ / NFR / AC / OPEN の正本）
- 設計: `docs/design.md`（モジュール分割・hooks 連携・UI はモック面 1a〜1f 準拠）
- 検証: `docs/verification.md`（V-01〜V-20）／実行記録: `docs/verification-results.md`

## 動作要件

- Windows 11 / Node.js 22+ / npm
- `curl.exe`（Windows 10+ 同梱。hooks からのイベント送信に使用）

## セットアップ

```
npm install
npm run build
```

## 起動

```
npm start
```

### 他の PC への導入（クローンから起動まで）

```
git clone https://github.com/kurocoma/terminal-app.git
cd terminal-app
npm install
npm run build
start-app.bat
```

- 前提は Node.js 22+ と `curl.exe`（Windows 10+ 同梱）だけ。設定・登録情報は `%APPDATA%\terminal-app\` に PC ごとに作られる
  （リポジトリには含まれない）。
- 起動後にプロジェクトのフォルダをウィンドウへドラッグ&ドロップすると、そのフォルダの `.claude/settings.json` に hooks が
  自動追記されて監視が始まる（既存設定は保全・バックアップ付き）。
- 品質ループ（eval-loop）の進捗バッジは `%USERPROFILE%\.claude\eval-loop\` がある PC でだけ出る。無ければ単に非表示になる。
- 2 回目以降の起動は `start-app.bat` だけでよい（ビルド済みなら再ビルドしない）。

- フォルダをウィンドウへドラッグ&ドロップするとプロジェクトが登録され、
  対象の `.claude/settings.json` に **Stop / Notification / UserPromptSubmit の 3 イベント**の
  hooks が自動追記される（既存設定は保全・バックアップ `settings.json.terminal-app.bak` 作成・冪等。
  UserPromptSubmit はプロンプト送信＝実行開始の検知用 — タイルが「実行中」（スピナー＋経過時間）になる）。
- **起動時追補**: アプリ起動時に登録済み全プロジェクトの hooks を冪等に再マージし、不足イベントのみ
  追記する。旧 2 イベント構成で登録済みのプロジェクトにも**再登録なしで** UserPromptSubmit が行き渡る。
- 自アプリ分の hooks は command 内の URL パス `/terminal-app/event` で識別する（`terminal-app` を
  パスに含むだけのユーザー自身の hook は除去・置換の対象にならない）。
- タイルをクリックすると、そのプロジェクトに設定した対象（Cursor / ターミナル）を前面化する。
- **未接続タイル**: クリックで開く対象アプリ（Cursor / ターミナル）でそのフォルダを開いているウィンドウが
  見つからないタイルは灰色で表示される（約 5 秒ごとに判定。実行中・確認待ちのタイルは誤判定で隠さないよう対象外）。
  ステータスバー右端の「未接続を表示」トグルで非表示にでき、設定は再起動後も保持される。
  右クリック →「立ち上げる」で対象アプリを開くと数秒で通常表示に戻る。
- **表示名**: タイル右クリック →「表示名を変更…」または設定画面の ✎ で、フォルダ名とは別の表示名を付けられる
  （空にするとフォルダ名へ戻る。前面化・切断検知の対象探索はフォルダ名のまま）。
  手動ステータスのバッジ（作業中／レビュー待ち等）は表示名の下の行に出る（260904_1 #1）。
- **確認待ちの見え方と復帰（260904_1 #2）**: 確認待ちのタイルは青で 1 秒周期に点滅する。完了・切断・確認待ち復帰の
  見直し（掃引）は 15 秒ごと。権限確認を許可して Claude が作業を再開した（transcript が更新された／Claude Code の
  登録簿 status が busy になった）ことを掃引で検知し、タイルは自動で「実行中」に戻る。
- **作業中の完了・切断誤判定の防止（260907_1）**: 品質ループ等で Stop hook が block されて Claude が続行した場合や、
  同期 fork・codex 待ちで本体 transcript が長く止まる場合でも、タイルを「実行中」に保つ（戻す）。根拠は Claude Code の
  登録簿 status=busy（cli 起動）、transcript の block 痕跡（`stop_hook_summary.preventedContinuation`。Cursor 起動でも使える）、
  subagent 記録（`<sessionId>/subagents/agent-*.jsonl`）の更新。Stop 受信で「完了」にした約 3.5 秒後に判定して
  まだ作業中なら「実行中」へ戻し、完了トーストはその判定の後に出す（block された Stop で誤通知しない）。
  登録簿が busy の間は切断判定をしない。block で戻ったタイルの作業テキストは block 理由のラベル（例「[Eval-loop iteration 1/4 | RESUME 1/3]」）。
- **ループ進捗バッジ（260907_2）**: 品質ループ（eval-loop）が動いているセッションのタイルには、名前の下に
  「ループ 2/4・codex 実装中 1分・最高 78点」のような青いバッジが出る（周回数は 1 始まり。段階は 計画中／実装中／採点中／判定中、
  codex ジョブが走っていればその役割と経過分。最高点は 2 周目以降）。ループが終わると「ループ終了・合格 92点」
  （上限到達／停止／時間切れ／停滞で停止／採点不能）を 30 分間だけ表示する。情報源は `%USERPROFILE%\.claude\eval-loop\registry\`
  （sessions / agents）から辿る state.json と `jobs/iter-NNN-<role>/` の heartbeat。15 秒ごとの掃引で更新。
  fork ループ（`registry/agents`）も state の session_id で対応付く。env `TERMINAL_APP_EVAL_LOOP_DIR` で参照先を差し替え可能（検証用）。
- **分割タイル（260904_1 #3）**: 1 つのフォルダで 2 本以上の claude が同時に動いている（Cursor の複数ターミナル等）と、
  タイルが「名前 ①」「名前 ②」（起動順）に自動で分かれ、それぞれの状態・作業テキストが見える。1 本に戻れば元の 1 タイルへ。
  生死は Claude Code 自身が書く登録簿（`%USERPROFILE%\.claude\sessions\<pid>.json`）とプロセス存在で判定するため、
  ターミナルを閉じれば約 30 秒以内（掃引 2 回）に枠が消える。分割タイルの右クリック →「この枠を消す」で手動でも消せる。
  ステータスバーの件数は表示タイル基準。
- **ウィンドウ位置の記憶／復元（260904_1 #3）**: タイル右クリック →「ウィンドウ位置」→「今のウィンドウ位置を記憶」で
  Cursor / ターミナルのウィンドウ配置（位置・サイズ・最大化）を `projects.json` に保存し、「記憶した位置へ戻す」で再現する。
  設定画面の「ウィンドウ位置」に全プロジェクト一括の記憶／復元ボタンがある（アップデート等で全部閉じたあとの復帰用）。
  右クリック →「立ち上げる」で開いた直後は、ウィンドウが現れ次第（最大 60 秒待ち）記憶した位置へ自動で動かす。
  記憶した位置がどのモニタにも掛からないときは復元しない。
- **タイルの並べ替えと自動整列（260906_1）**: タイルをドラッグして別のタイルの左半分（手前）／右半分（直後）へ落とすと
  並び替わる（分割タイル ①② はプロジェクト単位で一緒に動く）。タイトルバーの「自動整列」ボタンは、接続中のタイルを
  左上へ・未接続を末尾へ寄せる（各グループ内の相対順は維持。押したときの 1 回だけ）。並び順は `projects.json` の
  配列順そのもので、再起動後も保持される。
- **確認待ちを左上へ自動配置（260922_1）**: 確認待ち（青の点滅）のタイルは、並び順に関係なくグリッドの先頭（左上）に
  表示される（複数あれば元の相対順のまま先頭に並ぶ。分割タイル ①② はプロジェクト単位で一緒に動く）。これは表示上の
  並びだけで、`projects.json` の並び順（D&D で決めた順）は書き換えない — 許可して「実行中」に戻れば元の位置へ戻る。
  自動整列ボタンと D&D は引き続き `projects.json` の並びを基準に動く。分割タイルの中の確認待ち（例「dev ②」）も
  タイル単位で先頭へ出る（260922_3。①③… は元の順のままその後ろに並ぶ）。
- **Jev 判定（260922_2）**: TypeSafe AI の判断専用モデル Jev を「制御層の門番」として使い、次の 4 つを補う。(1) **返答待ち** — Claude が文章で質問して止まった Stop は「完了」でなく「返答待ち」（確認待ちと同じ青の点滅・左上・トースト「返答が必要です」）。(2) **確認待ちの危険度** — 権限確認のツール呼び出しが「取り消せない操作」「外部へ送る操作」「広範囲に影響」なら名前の下に赤い印。(3) **作業テキストの上書き防止** — 「はい」「A」「続けて」のような短い返事では作業テキストを前の依頼文のまま残す。(4) **停滞の疑い** — 実行中のタイルで同じ失敗を繰り返している・進展が無いと判定されると赤い印「停滞の疑い・…」。
  なお Claude Code が自動で差し込む枠（バックグラウンド作業の完了通知・貼り付け枠・スラッシュコマンドの記録・system-reminder）は
  作業テキストに出さない（260922_5。枠だけのプロンプトでは前の依頼文を維持し、貼り付けの外にある指示文があればそれを出す）。
  API キーは env `TYPESAFE_API_KEY` か `%USERPROFILE%\.typesafe.env` の `TYPESAFE_API_KEY=...`（console.typesafe.ai で発行）。無ければ・env `TERMINAL_APP_JEV=off` なら・API が失敗したら、これらの印が出ないだけで従来どおり動く。返答待ちのタイルは、ユーザーが返答した・Claude が続行した（transcript の終端が open）・登録簿が busy・Stop hook が続行を指示した、のいずれかで 15 秒以内に「実行中」へ戻る（260922_4。完了・切断と同じ復帰規則。後片付けの書き込みだけでは戻らない）。判定を待つ間に作業が再開していた場合は返答待ちにしない。判定結果は `app.log` に「Jev 〜判定:」で全件残る。transcript の抜粋（最後の返答・許可待ちのツール呼び出し・直近の手順）が米国の外部 API へ送られる点に注意（顧客データを扱うプロジェクトでは `TERMINAL_APP_JEV=off` で止める）。実 API の疎通結果: `docs/evidence/20260922-jev/probe-result.json`。
- **サブエージェント待ちも「実行中」（260922_8）**: 本体の応答が終わっていても、バックグラウンドのエージェント
  （Backgrounded agent・同期 fork・codex 委譲）が動いている間はタイルを「実行中」に保ち、青いバッジ「サブエージェント待ち」を出す。
  根拠は 2 つで、(1) `subagents/agent-*.jsonl` の更新が Stop より後（本体 transcript は Stop 直後の後片付けでも動くため見ない）、
  (2) Jev が最後の返答を「裏のエージェントに任せて待っている」と判定したとき。返答待ちと重なった場合はユーザーへの返答を優先する。
- **再起動しても続きから見える（260922_7）**: 表示中のセッション（状態・作業テキスト・確認待ち／返答待ち・危険度・停滞・名前の印・経過の起点）を
  `%APPDATA%	erminal-app\sessions.json` に随時保存し、次の起動で実データと突き合わせてから取り込む。
  突き合わせの規則は「登録が消えたプロジェクトは捨てる」「Claude Code の登録簿にプロセスが居なければ捨てる」
  「保存後に transcript が進んでいたら終端分類で作り直す（古い確認待ちを貼り付けない）」「動いていなければ保存時のまま」。
  保存から 24 時間以上たった記録・壊れたファイルは使わない（従来どおり作り直す）。
- **起動時復元（260922_3）**: セッション表示はメモリ上だけなので再起動直後は全タイルが「待機」になるが、起動時に登録済み全プロジェクトの transcript を走査し、Claude Code の登録簿（`~/.claude/sessions`）で生きているセッションを「完了」「実行中」で自動復元する（更新が何時間前でも生きていれば拾う。登録簿に無い古い transcript は拾わない）。完了で復元したものは Jev で「質問して止まっているか」を一括判定し、該当すれば「返答待ち」にする。タイル右クリック →「再接続」でも同じ判定が走る。結果は `app.log` の「起動時復元: … → Jev 返答待ち N 件」。
- **今やっているタスクの表示（260922_10）**: タイルの名前の下に、そのセッションが今やっているタスクを出す。
  出所は Claude Code 自身が transcript に書く `ai-title`（会話が進むと更新される）で、AI 呼び出しは不要。
  同じフォルダで複数のセッションが動いていても、分割タイル ①② ごとに別々のタスク名が出る。
- **表示名の自動変更（260922_10）**: Jev が「名前が作業を表していない」と判定したプロジェクトは、
  Claude Sonnet の提案でそのまま改名する（確認ダイアログなし）。歯止めは「一度自動で付けたプロジェクトは二度目をやらない」
  「同時に 1 件だけ」「失敗したら何も変えない」。止めたいときは `%APPDATA%	erminal-app\config.json` の
  `"autoRename": false`。付いた名前が気に入らなければ右クリック →「表示名を変更…」で上書きできる。
- **タイル名の見直し提案（260922_6）**: Jev が「表示名がその作業を表しているか」「表示名が汎用的すぎないか」を判定し、見直した方がよいタイルには名前の下に黄色の印（例「✎ 名前が作業を表していません」）が出る。判定は表示名か作業テキストが変わったときだけ（同じ材料では聞き直さない）。実測では `dev` のような汎用名が 0.98、具体名は 0.08〜0.41 で分かれた。
  タイル右クリック →「表示名を AI に提案（Claude Sonnet）」で、フォルダ名と直近の作業から新しい表示名を 1 つ作り、確認ダイアログで採用するとその場で改名する（Jev は文章を作れないため、名前の生成だけ Claude Code CLI の sonnet に任せる）。プロンプトは標準入力で渡し（複数行を引数にすると cmd.exe が壊す）、CLI の警告行は候補から外す。説明文が混ざったときは 1 回だけ言い直す。実測で 7〜70 秒かかる（上限 90 秒）。`claude` コマンドが無い・時間切れ・形式が想定外なら何も変えずステータスバーに理由を出す。
- 登録解除は設定画面（歯車アイコン）の各プロジェクト行の × ボタン。自アプリ分の hooks のみ除去する。
- トースト通知・サウンドは次期スコープ（REQ-12）。設定 UI は無効表示のみで音は鳴らない。

### Orca で使う（261005_1）

[Orca](https://github.com/stablyai/orca)（複数エージェントを 1 枚の窓で動かす Electron アプリ）をクリック先に選べる。
設定画面のプロジェクト行で `Cursor / Orca / ターミナル` を選ぶか、「クリックで開くアプリ（一括）」で全プロジェクトをまとめて切り替える
（一括で選んだ値は、以後新しく登録するプロジェクトの既定にもなる）。

- Orca の窓はタイトルが常に「Orca」でフォルダ名を含まないため、Orca 同梱の CLI
  （`%LOCALAPPDATA%\Programs\orca\resources\bin\orca.exe`）でフォルダ・ターミナルを調べる。PATH への登録は不要。
- タイルをクリックすると Orca の窓を前面化し、続けてそのセッションが動いている Orca 内のタブへ切り替える
  （0.5 秒ほど遅れて切り替わる）。タブは Orca の hook 状態ファイル（`%APPDATA%\orca\agent-hooks\last-status.json`）の
  セッション ID で特定し、見つからなければフォルダとエージェントの状態（確認待ち・実行中）から選ぶ。
- 未接続（灰色）: Orca が起動していない、またはそのフォルダのターミナルが Orca に無い。
  右クリック →「立ち上げる」で Orca にこのフォルダのターミナルを作る（Orca 未起動なら起動し、未登録フォルダなら Orca に追加する）。
- **画面プレビュー**: Orca 対象のタイルにマウスを 0.6 秒ほど置くと、そのセッションの Orca ターミナル画面の末尾が出る（読み取りのみ）。
- **あなたの指示**（261005_3。Orca 以外のタイルも対象）: タイルにマウスを置くと、そのセッションで送った指示が新しい順に 3 件出る
  （返信パネルでは 5 件）。Claude は transcript の末尾 2MB から、Codex は履歴 DB（`~/.codex` と Orca 用の保存先の両方）から読む。
  ツールの戻り値・Claude Code が差し込む枠（system-reminder 等）・サブエージェントの指示は除く。本文はログに残さない。
- **返信・中断**: タイル右クリック →「Orca: 画面を見て返信…」でパネルを開くと、画面（約 2 秒ごとに更新）を見ながら 1 行の返信を送れる。
  「中断（Esc）」は実行中の処理を止める Esc キーを送る（Ctrl+C は 2 回でエージェントが終了するため使わない）。
  送信できるのは、Orca の状態ファイルでセッションのターミナルを正確に特定できたときだけ（推定で選んだターミナルには送らない）。
  改行は空白にまとめて 1 行で送る。送った本文と画面の内容はログに残さない（文字数のみ）。
- **変更ファイル**: タイル右クリック →「Orca で変更ファイルを開く（差分）」で、git の変更ファイルを Orca の差分タブで開く。
- **スリープ**（261005_4）: Orca でワークスペースをスリープにする（ターミナルを全部閉じる）と、タイルは灰色の「未接続」ではなく
  「☾ スリープ中（Orca）」になる（点線枠・やや薄く）。Orca の「スリープ」は専用の記録を持たないため、
  「Orca に登録済みで生きているターミナルが 0」をスリープ中とみなす（Orca で一度も開いていないフォルダも同じ扱い）。
  スリープでエージェントが止まっても「切断」の通知は出さない。クリックすると Orca を前面に出すだけで、
  起こすときは右クリック →「起こす」（このフォルダのターミナルを作る）。実行中・確認待ちの表示はスリープより優先する。
- **Codex の承認待ち**: Orca で動かしている Codex がツールの承認待ちになると、タイルを「確認待ち」にする（Codex の履歴だけでは
  承認待ちを確定できないため、Orca の状態で補う）。クリック先の設定に関係なく、Orca が起動していれば使う。
- Claude Code の hooks は Orca 内でもそのまま動く（Orca 自身も `~/.claude/settings.json` に自分の hook を追加するが干渉しない）。
- Orca が新しく作るワークツリー（`~/orca/workspaces/...`）で動かしたセッションは、登録フォルダと場所が違うためタイルに出ない。
- CLI の接続トークン等は orca.exe 自身が読む。本アプリはトークンを読まず、CLI の出力本文もログに残さない（エラーコードのみ）。

## テスト・検証

### Codex の状態表示

登録済みのプロジェクトで使っている Codex は、アプリ起動時と約 5 秒ごとに自動で読み取り、
「Codex」の印があるタイルに表示する。同じフォルダで Claude Code と併用すると分割タイルになる。
Codex CLI、Cursor の Codex 拡張、Codex アプリのローカル会話が対象。
Codex 側の設定変更や hook の追加は不要で、再起動後もローカル履歴から表示を復元する。

- 対応する状態は実行中・完了・エラー、および Codex が構造化データで記録した質問の返答待ち。
  ツールの権限承認待ちは履歴から確定できないため、専用の検知対象には含まない（Orca で動かしている Codex だけは、
  Orca の状態から「確認待ち」にする。「Orca で使う」参照）。
- 直近 24 時間に更新された未アーカイブの対話を対象にする。サブエージェントや `codex exec` の自動処理は除く。
  Windows では会話の writer lock も読み取り、開いているセッションを表示する。応答完了後もターミナルを
  開いていれば残り、閉じると通常約 10 秒以内（2 回の確認）に分割から外れる。
  Claude と併用していても終了履歴を分割へ戻さず、全て閉じたときはプロジェクトの最後の状態を 1 枚だけ残す。
  残した終了履歴は、Cursor / ターミナルのウィンドウも無ければ Claude と同じ「未接続」（灰色）になる。
- writer lock のない旧版・判定不能時は従来の履歴選定（実行中・返答待ちと直近完了 1 件）を使う。
  この場合はターミナル数との連動を保証できない。lock の取得・作成・削除は行わない。
- 実行中のまま 30 分以上更新されない会話は「切断」とする。
  Codex が更新すると次の読み取りで状態を戻す。「切断」はプロセス終了の断定ではない。
- 読み取り先は `CODEX_HOME`、未指定なら `%USERPROFILE%\.codex`。Orca を入れている PC では、Orca が Codex に渡す
  `%APPDATA%\orca\codex-runtime-home\home` も合わせて読む（同じ会話は新しい方を採用。生存判定は見つかった保存先の lock で行う）。
  `state_5.sqlite` と `thread_history_1.sqlite` を読み取り専用で開き、Codex の設定・会話データには書き込まない。
  会話本文をログに記録したり、Jev / 自動改名へ渡したりしない。
- 現行ローカル DB 形式（Codex CLI 0.157.0 で確認）に対応。旧版で DB が無い場合や形式変更時は取得できない。
  読み取りの一時的な失敗は再試行し、30 秒以上続く場合は古い実行中・返答待ち表示を「切断」にする。
- 停止する場合は `%APPDATA%\terminal-app\config.json` に `"monitorCodex": false` を設定して再起動する。
  タイルをクリックした際の移動先は従来どおりプロジェクトの Cursor / Orca / ターミナル設定に従う。
- 検証用に `TERMINAL_APP_CODEX_HOME` と `TERMINAL_APP_CODEX_POLL_MS` を指定できる。
  `TERMINAL_APP_DATA_DIR` を指定した検証では、前者の明示指定がない限り実際の Codex 履歴は読み取らない。

## データ・ログの場所

- 設定・登録情報: `%APPDATA%\terminal-app\`（`projects.json` / `config.json`）
- ログ: `%APPDATA%\terminal-app\logs\app.log`（日次ローテーション・7 日保持）
- 通常の動作ログはファイルだけに保存する。`start-app.bat` はアプリの標準出力・標準エラーを切り離し、
  Cursor 内の Codex などの入力欄にログや起動時の警告が混ざるのを防ぐ。
- 環境変数 `TERMINAL_APP_DATA_DIR` でデータディレクトリを差し替え可能（テスト・デモ用）
- 環境変数 `TERMINAL_APP_WINDOW_POLL_MS` で未接続タイル判定（ウィンドウ列挙）の間隔を変更可能（既定 5000ms。検証用）
- 環境変数 `TERMINAL_APP_LIVENESS_INTERVAL_MS` で掃引（終了・切断・確認待ち復帰・登録簿の生死判定）の間隔を変更可能（既定 15000ms。検証用）

## 既知の制約（MVP）

- アプリ未起動中のイベントは取りこぼす（design.md 3.3 の採用仕様）
- エラー検知の網羅範囲（クラッシュ等）は OPEN-03 として技術検証待ち。受信形式は design.md 4.8 で定義済み
- セッション状態は揮発（再起動で全タイル「待機」に戻る）
