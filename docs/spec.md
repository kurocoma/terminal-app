## 1. 背景・目的・成功基準

### 1.1 背景

Claude Code CLI を約 6 プロジェクト並行で稼働させており、完了通知がどのプロジェクトのものか識別しづらい。完了・許可待ちに気づくのが遅れると、その分だけ並行作業全体が停滞する。

### 1.2 目的

**どのセッションが止まったかをひと目で識別し、1 クリックで対象ウィンドウに切り替える**ための常駐タイルダッシュボードアプリ（Windows 11）を作る。

### 1.3 成功基準

| ID | 成功基準 | 確認方法 |
|----|----------|----------|
| SC-1 | 並行セッションの状態変化（完了・確認待ち・エラー）に、視界の隅でも気づける（発光表現） | AC-04〜AC-07 |
| SC-2 | タイル 1 クリックで対象ウィンドウ（Cursor またはターミナル）が前面化する | AC-09 |
| SC-3 | プロジェクト登録が D&D だけで完了し、hooks 設定を手作業で編集しない | AC-01, AC-02 |

## 2. 利用者・利用シーン

- **利用者**: 本人のみ（開発者 1 名）。多人数利用・配布は想定しない。
- **環境**: Windows 11 ローカル。ネットワーク公開なし。

| シーン | 期待する挙動 |
|--------|--------------|
| 複数プロジェクトで Claude Code を並行起動し、別作業をしている | タイルは静かに「実行中」表示（スピナー＋経過時間）で邪魔をしない |
| どれかのセッションが応答を終えた | 該当タイルが「完了」（緑）で呼吸発光し、視界の隅で気づける |
| ツール実行の許可や質問で停止した | 該当タイルが「確認待ち」（アンバー）で呼吸発光する（放置防止） |
| セッションが異常終了した | 該当タイルが「エラー」（静的な赤）になる |
| 気づいたタイルをクリックする | 設定済みの対象（Cursor／ターミナル）のウィンドウが前面化する |
| 新しいプロジェクトを監視したい | フォルダをウィンドウへ D&D するだけで登録が完了する |

## 3. スコープ

### 3.1 やること（MVP = コアのみ）

**D&D 登録 → 状態検知 → タイル点灯 → クリックで前面化**（壁打ちノートの MVP 線引きどおり）。

### 3.2 やらないこと（MVP 外）

| 項目 | 位置づけ |
|------|----------|
| OS トースト通知・サウンド | **次期（should）**。希望あり・設定で ON/OFF できる前提。モック 1d に通知音トグルがあるが、MVP では無効化して提供する（REQ-12、design.md 6.4 参照） |
| 完了履歴・タイムライン表示 | 次期候補（could） |
| トレイ常駐時のコンパクト 1 行バー表示 | モック側「次の一手」メモの調整候補。未確定（OPEN-05） |
| macOS / Linux 対応 | 対象外（Windows 11 のみ） |
| ネットワーク公開・複数人利用 | 対象外（本人のみ・ローカル） |
| Claude Code 以外のツールの監視 | 対象外 |

## 5. データ・業務ルール

### 5.1 タイルの 4 状態の定義

| 状態 | 意味 | 主な検知イベント | 表示（モック準拠） |
|------|------|------------------|--------------------|
| 実行中 | Claude Code が作業中 | hooks: UserPromptSubmit（プロンプト送信。OPEN-04 解消 — design.md 4.5、2026-07-11 案 A 採用） | ニュートラル＋スピナー＋経過時間（例 1:24:01） |
| 完了 | 応答が終わり入力待ちに戻った（**最も目立たせる**） | hooks: Stop | 緑 ✓＋呼吸発光＋相対時刻（「完了・2分前」） |
| 確認待ち | ツール実行の許可や質問で停止中（放置すると進まないため通知価値が高い） | hooks: Notification | アンバー ?＋呼吸発光＋相対時刻 |
| エラー | 異常終了 | 検知の網羅範囲は OPEN-03（design.md 4.4） | 静的な赤 ⚠（発光アニメーションなし）＋相対時刻 |

補助表示: 登録直後でイベント未受信のタイルは、4 状態のいずれでもない「待機（イベント待ち）」としてニュートラル無発光で表示する（4 状態の定義は変えない。design.md 5.1 参照）。

### 5.2 状態遷移（概要）

登録 →（待機）→ 実行中 ⇄ 確認待ち → 完了 → 実行中 …、任意の状態からエラーへ遷移しうる。遷移表の正本は design.md 5.1。

テキスト遷移図（2026-07-11 追記。`[ ]` = 状態、`--x-->` = 入力 x による遷移）:

```
登録 --> [待機]
[任意の状態] --Stop--> [完了]                     （エラーからの復帰を含む）
[任意の状態] --Notification--> [確認待ち]         （確認待ち中は時刻のみ更新）
[任意の状態] --実行開始(OPEN-04)--> [実行中]      （実行中の継続は起点を維持）
[任意の状態] --エラー検知(OPEN-03)--> [エラー]
アプリ再起動 --> 全タイル [待機]（セッション状態は揮発）
```

### 5.3 hooks イベントとの対応

| hooks イベント | 遷移先状態 |
|----------------|-----------|
| Stop | 完了 |
| Notification（許可要求・入力待ち通知） | 確認待ち |
| UserPromptSubmit（プロンプト送信。2026-07-11 OPEN-04 案 A 採用で追加） | 実行中 |

マッピング詳細（Notification の種別判定、エラー・実行中の扱い）は design.md 4.3〜4.5 を正本とする。

### 5.4 複数セッションの扱い

同一プロジェクトで複数セッションが並行する場合、**直近イベントのセッションを優先表示**する（壁打ちノートの前提。詳細規則は design.md 5.2）。

## 6. 非機能要件

| ID | 分類 | 要件 | 受入基準 |
|----|------|------|----------|
| NFR-01 | 性能 | イベント発火からタイル反映まで 1 秒以内（ローカル通信） | AC-04 |
| NFR-02 | 無害性 | 本アプリが未起動・応答不能でも Claude Code セッションを阻害しない（hook コマンドは短いタイムアウトで失敗しても本体を止めない） | AC-14 |
| NFR-03 | 安全性 | `.claude/settings.json` を破壊しない（追記前バックアップ・アトミック書き込み・既存 hooks 保全。パース不能時は書き込まない） | AC-02, AC-03 |
| NFR-04 | セキュリティ | イベント受信は 127.0.0.1 バインドのみ。外部公開しない | V-19（verification.md） |
| NFR-05 | レイアウト | タイル最大 12〜16 でレイアウトが破綻しない | AC-15 |
| NFR-06 | 視認性 | 発光は点滅ではなく約 2.4 秒周期の「呼吸」。エラーは動かない赤（= 止まっている記号）。**例外（260904_1 #2）**: 確認待ちだけはユーザー指示により青（アクセント色）の 1 秒周期の点滅とし、見落としを防ぐ | AC-06 |
| NFR-07 | 常駐負荷 | アイドル時に CPU をほぼ消費しない（目安: アイドル時 CPU 1% 未満） | V-20（verification.md） |

## 7. 制約・前提

- Windows 11 / 利用者は本人のみ / ローカル動作・ネットワーク公開なし。
- タイル数は最大 12〜16 を想定してレイアウト設計（現状 6 個＋余裕）。
- 検知は Claude Code の hooks 仕様（`.claude/settings.json`、Stop / Notification イベント）に依存する。
- UI はモック（面 1a〜1f、`context-design-mock.md`）を正とする。モック側「次の一手」メモは未反映の調整候補として扱う（OPEN-05）。
- **検討して却下した案**（再検討しない前提）: ローカル Web アプリ形態（他アプリの前面化に制約があるため常駐デスクトップを採用）／hooks の手動設定（「簡単な UI/UX」に反するため自動追記を採用）。
